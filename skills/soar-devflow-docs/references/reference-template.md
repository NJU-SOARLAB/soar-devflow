# 说明页（`reference/`）8 段式写作模板

适用于把关架构、排查疑难问题、复用算法/协议或深入理解系统原理的研发人员。回答：**“这套模块怎么设计的？逻辑是否严谨？在哪里改、怎么复现验证？”**

## 推荐结构

1. **开篇概述与设计边界 `{#overview}`**：直接写结论，明确本模块做什么、**不做什么**、核心不变量。
2. **核心模型与公式**（如涉及算法/物理/调度）：用 LaTeX 写出实际实现的方程，逐一定义变量、单位与坐标系。
3. **数据流 / 状态机 `{#dataflow}`**：使用 Mermaid（`flowchart` / `sequenceDiagram` / `stateDiagram-v2`）或手写 SVG（带浅色底板以适配明暗主题）。
4. **关键参数与配置表**：名称、默认值、单位/类型、真实来源文件路径。
5. **实现位置**：列出核心代码路径及其单一职责（放在列表而非窄表单元格中）。
6. **如何复现与验证 `{#verification}`**：给出真实测试命令、基准脚本或验证报告路径，以及预期指标范围。
7. **已知局限与常见误读**：哪些能力尚未验收、哪些做了近似、哪些界面或日志数值容易误解。
8. **核查发现**（如有）：写作时对照代码发现的文档与实现偏差或可疑边界，如实列出，不粉饰。

## 质量基线

- 每个数值、配置键与文件路径均须从当前代码直接核实。
- 至少包含 1–2 张架构/数据流图（Mermaid 或 SVG）以及必要公式或契约表。
- 文末给出“操作步骤见 `../guide/...`”指向对应教程页。
