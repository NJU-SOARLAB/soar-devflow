# 拆解、双口径估时与排期

仅在拆解大型需求或重新排期时读取；日常进度更新不重算全表。

## 拆解原则

- 按**可独立交付与独立验收**拆分任务与子任务；父子层级用于聚合范围，不自动等同先后依赖。
- 原生前置（`prev`）和 Base 关联只记录**因果必要条件**（缺少前置产物会导致本任务无法实施）。复用偏好、人工等待或审核节奏另行记录在“验收与等待说明”。

## AI 实施窗口 vs 交付/验收窗口

大型人机协作项目中，Agent 编写/测试代码的速度与人类评审/硬件验证的节奏量级不同，必须把两条时间线分开记录：

1. **AI 开发估算（小时）**：已有基础且边界清晰的任务通常按 0.25–1 小时评估；跨模块集成约 1–3 小时；高不确定性探索明确列出未知项。只计实现、必要自动验证与按需技术文档。
2. **人工验收与外部等待（单列）**：设计评审、主观体验确认、硬件/实验排期、长耗时训练或压测单列于 `人工验收估算小时` 与 `验收与等待说明`。
3. **两条时间线**：
   - `AI计划开始` / `AI计划交付`：Agent 实施参考窗口（未知容量默认按单条参考线、每日最多 8 小时估算，仅作排期参考，不是开工许可或超时红线）。
   - 原生任务 `计划开始` / `计划截止`：面向人类审阅与里程碑的交付/验收目标窗口。
   - 父任务作为聚合项不重复累加子任务工时（可设为 `0` 表示汇总任务）。
4. **重排纪律**：优先尊重用户明确指定的日期；仅在授权重排时调整受影响的下游日期，始终保留远端最新完成状态，不倒填虚构历史工时。
